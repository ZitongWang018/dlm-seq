## 0. 一句话结论

1. **早期「从轨迹恢复正确答案」方向在数学上基本被否证**：GSM8K 错题答案区 ceiling ≈ 0%（观测）；MATH 上报的 ceiling=0% **需谨慎**——最新实现存在分母/阈值 bug（见 `0712grokproblem` P1），修后再解释。
2. **轨迹仍有用，但角色应改写**：横向响应看「落定影响了谁」，纵向演化看「影响是否被吸收」；更适合做风险诊断 / 分支选择 / 区域调度，不适合直接融合旧 logits。
3. **当前最强、可复现的正结果是区域级顺序解码**：固定 32-token 分块在 GSM8K-400 上达到 **71.25%**，同 NFE 下单块 LCR 为 **58.75%**（McNemar \(p=2.02\times10^{-6}\)）。这是结构层结果，尚不是「由轨迹自动决定区域边界」的最终方法。
4. **尚未闭环**：用轨迹在区域边界自动扩/缩并行范围的假设仍在验证；按逐步 response 控制波前的尝试已失败。

## 1. 问题设定

### 1.1 我们在研究什么

掩码扩散语言模型（DLM）在序列 \(\mathbf{x}^{(t)}\) 上维护一组仍为 mask 的位置集合 \(\mathcal{M}_t\)。每一步前向给出全序列 logits，从而对每个 \(i\in\mathcal{M}_t\) 得到完整候选分布

\[
p_t(v\mid i) = \mathrm{softmax}\big(\ell_t(i)\big)_v,\qquad \ell_t(i)\in\mathbb{R}^{|V|}.
\]

标准采样器（如 LCR）每步只把 \(k_t\) 个位置从 mask **落定（commit）** 为具体 token，其余位置的分布通常被丢弃。本研究主张：这些中间分布构成可观测的**推理状态**。

| 视角 | 含义 | 典型观测 |
|------|------|----------|
| **纵向（longitudinal）** | 固定位置 \(i\) 上 \(\{p_t(\cdot\mid i)\}_{t}\) 如何演化 | flip、路径长度、Jaccard、path efficiency |
| **横向（lateral）** | 一次 commit 后，其他 \(j\in\mathcal{M}\) 的分布如何被改写 | top-\(k\) 支持上的 L1 / KL、近邻 vs 远邻 |

### 1.2 研究目标

开发一种 **training-free** 的 DLM 推理方法：

- 用去噪时间轴上的分布轨迹作为状态；
- 在尽量多的样本上超过 LCR 基线；
- 额外代价可控（分支类目标大致 1.1×–1.4× NFE；区域解码路线争取 **等 NFE**）。

### 1.3 基线配置（GSM8K 默认）

| 项 | 值 |
|----|-----|
| steps \(T\) | 64 |
| gen_length \(L\) | 128 |
| block_length \(B\)（单块基线） | 128 |
| temperature | 0.0（确定性 argmax） |
| mask_id | 126336 |
| 主评测集 | GSM8K（多切片：50 / 200 / 400 / 40） |
| 辅评测集 | MATH、HumanEval、MBPP |

约束（代码断言）：\(L \bmod B = 0\)，且 \(T \bmod (L/B) = 0\)。块数 \(N_b=L/B\)，每块步数 \(T_b=T/N_b\)。

## 2. 算法详解（公式 + 文字）

### 2.1 核心 reframing（2026-07-10 之后）

**旧问题（已基本否定）：**

> 能否从历史分布中恢复 / 融合出更好的 token？

**新问题：**

> 一次分布变化意味着什么——是位置自身的不确定性，还是对新可见上下文的响应？轨迹应决定**时机、依赖、分支与区域范围**，而不是直接投票旧 logits。

关键经验：数学题上许多错答表现为 **stable wrong**——正确答案 token 从未在答案区成为 argmax。因此「身份稳定性 / Jaccard / 历史最高置信度」等假设「正确候选曾出现」的方法前提不成立（GSM8K 侧证据较强；MATH ceiling 见审计 caveat）。

---

### 2.2 符号与公共子程序

记 prompt 长度为 \(P\)，生成区下标 \(i\in\{P,\ldots,P+L-1\}\)。第 \(t\) 步：

1. 前向：\(\boldsymbol{\ell}_t = f_\theta(\mathbf{x}^{(t)})\)（可选 CFG，此处省略）。
2. 预测 token：\(\hat{x}_t(i)=\arg\max_v \ell_t(i)_v\)（\(T_{\mathrm{emp}}=0\) 时无 Gumbel）。
3. 置信度：

\[
c_t(i) = p_t\big(\hat{x}_t(i)\mid i\big) = \mathrm{softmax}(\ell_t(i))_{\hat{x}_t(i)}.
\]

4. **每步落定配额**（`get_num_transfer_tokens`）：对当前块内仍 mask 的数量 \(m\)，在 \(T_b\) 步上尽量均分：

\[
k_t = \Big\lfloor\frac{m}{T_b}\Big\rfloor + \mathbf{1}\big[t < (m \bmod T_b)\big],
\qquad \sum_{t=1}^{T_b} k_t = m.
\]

因此只要走满块内步数，块内 mask 会全部清空（NFE 计数的是前向次数，不是「每步只解 1 个」）。

5. **落定**：在允许集合 \(\mathcal{S}_t\) 上按分数选 top-\(k_t\)，令这些位置 \(x\leftarrow\hat{x}_t\)，移出 mask。

---

### 2.3 基线：LCR（Low Confidence Remasking / 高置信优先落定）

**文字**：每步在**当前活跃块**的仍遮蔽位置上，按置信度从高到低落定 \(k_t\) 个；低置信位置继续保持 mask，等待更多上下文。名称里的 remasking 对应「未选中的继续遮住」。

**分数**（实现中对 LCR / `lcr_probe` 等）：

\[
s_t(i) = c_t(i).
\]

**选择**：

\[
\mathcal{C}_t = \mathrm{TopK}_{k_t}\big\{ s_t(i) : i\in\mathcal{S}_t\big\},
\qquad
\mathbf{x}^{(t+1)}_i =
\begin{cases}
\hat{x}_t(i), & i\in\mathcal{C}_t,\\
\mathbf{x}^{(t)}_i, & \text{otherwise}.
\end{cases}
\]

单块基线：\(B=L=128\)，\(N_b=1\)，\(T_b=64\)。  
`lcr_probe`：**输出与 LCR 相同**，额外记录横向/纵向诊断，用于风险分析而不改路径。

---

### 2.4 区域顺序解码（当前最强正结果）

**文字**：把生成区切成连续块，**块与块之间串行**：只有块 \(b\) 全部去掩后，才开始块 \(b+1\)。块内仍用 LCR 多步并行落定。这在结构上强制「前文区域先成为可见上下文」，对应横向依赖应在区域尺度解决的假设。

**块边界**：

\[
\mathcal{B}_b = \big[P + bB,\; P + (b+1)B\big),
\qquad b=0,\ldots,N_b-1.
\]

第 \(b\) 块内，可选取位置必须满足 \(i\in\mathcal{B}_b\cap\mathcal{M}_t\)（多 block bug 修复后的约束）。

**等 NFE 对照**（GSM8K 默认 \(T=64,L=128\)）：

| 设置 | \(B\) | \(N_b\) | \(T_b\) | 总 NFE |
|------|------:|------:|------:|-------:|
| 单块 LCR | 128 | 1 | 64 | 64 |
| 四块区域 | 32 | 4 | 16 | 64 |
| 八块 | 16 | 8 | 8 | 64 |
| 两块 | 64 | 2 | 32 | 64 |

固定 \(B=32\) 在 GSM8K-400 上显著优于单块（见 §5.3）。**固定分块本身还不是最终「轨迹方法」**——最终主张应是由轨迹决定 \(B\) 或下一区域范围。

---

### 2.5 横向响应（lateral response）

**文字**：把一次真实 commit 看作对可见上下文的干预。比较仍遮蔽位置在 commit **前后**的候选分布；变化大 ⟹ 该位置依赖刚出现的上下文，不宜与「被依赖的源」在同一步当作独立并行落定。

**Top-\(k\) 状态**：对位置 \(i\)，

\[
\mathcal{U}_k(p) = \text{概率最大的 }k\text{ 个 token 及其概率}.
\]

**支持上的 L1**（实现 `_topk_state_l1` / `_topk_l1`；必须用 **token id** 建支持，不能用概率值当下标）：

\[
\delta_t(i) = \sum_{v\in \mathrm{supp}_{k}(p_{t-}^{\cdot|i})\cup\mathrm{supp}_{k}(p_{t}^{\cdot|i})}
\big| p_{t}(v\mid i) - p_{t-}(v\mid i) \big|,
\]

其中 \(t-\) 表示**上一 commit 之后、本步更新前**缓存的 top-\(k\) 状态。未出现在某侧 top-\(k\) 的概率按 0 计。

**KL**（诊断用，同样在并集支持上归一）：

\[
\mathrm{KL}\big(p\|q\big)
= \sum_{v\in\mathcal{S}} p_v \log\frac{p_v}{q_v},
\quad
\mathcal{S}=\mathrm{supp}_k(p)\cup\mathrm{supp}_k(q).
\]

**近邻 / 远邻**：给定上一批已落定位置集合 \(\mathcal{C}_{t-1}\) 与窗口 \(w\)（默认 4），

\[
\delta^{\mathrm{near}}_t
= \mathrm{mean}\{\delta_t(i): \exists c\in\mathcal{C}_{t-1},\,|i-c|\le w\},
\quad
\delta^{\mathrm{far}}_t
= \mathrm{mean}\{\delta_t(i): \text{其余仍 mask}\}.
\]

样本级风险常用 **selected-response delta**（被选中落定位置的响应均值等聚合），在 GSM8K 上作错误风险时 AUC ≈ 0.65–0.68（可复现）。

**约束**：

- 横向只说明**依赖存在**，不直接说明哪个候选正确；
- **不能**推出「\(\delta\) 越大就越应延迟落定」——逐步按 response 改顺序/缩波前的实验已失败。

---

### 2.6 纵向轨迹（longitudinal）

**文字**：对横向上被改写的位置，继续看后续步分布是「保持新方向」还是「回摆」。关注的不是单纯「多久没换 top-1」，而是 **commit 引起的分布改变是否持续**。

**Flip 计数**（位置 \(i\) 在仍 mask 期间）：

\[
F(i) = \sum_{t} \mathbf{1}\big[\hat{x}_{t}(i)\neq\hat{x}_{t-1}(i)\big].
\]

答案区 / 推理区分别对位置集合取均值，用于错误**检测**（错题答案区 flip 约高 70%），在 T=0 下不足以**纠正**。

**路径长度 / 净位移（早期 Round1，轻量轨迹）**：对相邻步分布距离累加得 path length；相对锚点分布的距离为 net。早期 path/net 极大且分类全 frozen，后因度量与 reframing 弃用为主决策量。

**Path efficiency**（alignment / 稀疏探针用）：给定同一位置上的三段 top-\(k\) 状态 \((A,B,C)\)（先前 → 当前 → 提议），

\[
\mathrm{eff}(A,B,C)
= \frac{\|A-C\|_1}{\|A-B\|_1 + \|B-C\|_1 + \varepsilon}.
\]

\(\mathrm{eff}\approx 1\) 表示 \(C\) 沿 \(A\to B\) 方向继续；偏小表示回摆。用于「提议的上下文改变是否延续已有轨迹」。

**约束**：纵向稳定 ≠ 答案正确；不宜单独用来改写答案 token。

---

### 2.7 二者统一的决策图景（当前主线）

```
落定(commit) → 横向响应 δ（谁被改写）
                 ↓
           纵向轨迹（改写是否保持 / 回摆）
                 ↓
        区域级决策（何时扩大 / 缩小并行范围）
```

**已验证的落实**：固定区域顺序解码（§2.4）。  
**待验证的最终方法（H6）**：仅在**区域完成后**，用该区域造成的横向响应 + 响应的纵向保持/回摆，共同决定下一区域范围；二者一致时才扩大并行落定。  
**已失败的落实**：每一步用 \(\delta\) 直接改 commit 分数或波前宽度。

### 2.8 已实现变体（公式级摘要）

下列均在 `generate_with_sampler` 中；多数为负结果或小增益，保留作对照。

#### （1）Response boost / delay

\[
s_t(i)=
\begin{cases}
c_t(i) + w\cdot\min(\delta_t(i),\,C_{\mathrm{cap}}), & \text{boost 类},\\[4pt]
c_t(i) - w\cdot\min(\delta_t(i),\,C_{\mathrm{cap}})\cdot\mathbf{1}_{\mathrm{delay}}(i), & \text{delay 类}.
\end{cases}
\]

gated / strong 变体对 \(\delta\)、置信上界 \(c\le c_{\max}\) 等加开关。结论：单路径常伤基线；作第二分支时 oracle 有头空间，选择器是瓶颈。

#### （2）Response budget

强响应时缩小本步落定批量：

\[
k' = \max\!\Big(1,\;\big\lfloor k\cdot \alpha\big\rfloor\Big)
\quad\text{当}\quad
r_{\mathrm{resp}}\ge\tau,
\]

否则保持原 \(k\)（`response_budget_transfer_count`）。实验掉点。

#### （3）Refresh / Lookahead

- **Refresh**：高响应步先落定锚点，再前向刷新后选其余位置（增 NFE），GSM8K-20 大幅掉点。  
- **Lookahead**：临时试 commit 两个候选，比局部后验置信，再沿较好探针继续；持平或略差。

#### （4）Wavefront

维护活跃波前集合 \(\mathcal{W}_t\)，\(|\mathcal{W}|\le W\)（默认 8）。只从 \(\mathcal{W}_t\cap\mathcal{B}_b\) 中选位置；落定后按半径 \(R\) 扩张邻域。  
**Response-decay wavefront**：若本步 \(\delta^{\mathrm{near}}\) 相对上步上升，则临时 \(R\leftarrow 1\)（收窄），否则扩张。  
40 样对照：固定分块 72.5% > 固定波前 65% > response 波前 55%。

#### （5）风险门控双分支 / Agreement

1. 跑 `lcr_probe` 得路径 A 与风险分数 \(r\)（如 selected-response delta）。  
2. 若 \(r\ge\tau\)，再跑独立路径 B（如 strong-response 或另一短推导）。  
3. 选择器：诊断规则 / 答案一致性 / answer-evidence 等。

独立 agreement 在 GSM8K-200 曾 +2.0 @ ~1.2×，跨 400 切片失败，合 600 样 McNemar \(p=1.0\) → **否决为可靠方法**。Answer-evidence 在 holdout 负向泛化。

#### （6）Flip-gated Best-of-2

若答案区 \(\bar F > 3.5\)，再生成一次；同意则输出，否则取 flip 更低者。T=0 时两次完全相同 → 增益 0。

#### （7）早期 Traj / RCR（Round2，已弃为主线）

- RCR：\(s=\max(c_{\mathrm{hist}}, c_t)\)（历史最高置信）。  
- Traj：收敛/稳定性加权组合（实现系数约 \(0.45\,c_{\max}+0.30\,c_t+\cdots\)）。  
结果：62%→58%，诊断量被当成硬排序量。

### 2.9 Ceiling（H4）定义

对错题，检查答案相关位置上，gold token 是否曾在任意步成为 argmax：

\[
\mathrm{ceiling\text{-}ratio}
= \frac{
\#\{\text{错题}:\ \rho>\tau\}
}{
\#\{\text{错题}\}
},
\qquad
\rho=\frac{\#\{\text{答案位曾命中 gold}\}}{Z}.
\]

- **GSM8K（历史）**：答案区约最后 15 位；上报 ceiling=0%，Idea Tree 记「fallback 启发式下 gold 从未出现」。  
- **MATH（当前脚本）**：\(Z=30\)（固定窗口长度）且 \(\tau=0.3\) → 短答案几乎不可能 \(\rho>0.3\)（**实现 bug**，见 `0712grokproblem` P1）。  
- **HumanEval（当前脚本）**：对 body 位对齐 `canonical_solution`；另有 prompt 重复拼接问题（P2/P3），ceiling 不可直接采信。

### 2.10 已明确排除的三条路线

| 排除项 | 原因 |
|--------|------|
| 融合 / 投票历史 logits | Round2 伤基线；正确候选常不在轨迹里（GSM8K） |

| 每一步按 response 大小频繁改范围 | delay / refresh / wavefront 等伤基线或无增益 |

### Round 5+ — Reframe：横向/纵向作为风险与结构信号（2026-07-10～12）

主要尝试与结论（详见 `PROJECT_STATE.md` / `MEMORY.md`）：

| 方向 | 代表结果 | 结论 |
|------|----------|------|
| Response delay / stability delay | 60%→58%、50%→45% | 直接改 commit 顺序过激，伤基线 |
| Response boost / strong branch | 单支弱于 LCR；oracle 有头空间 | 分支多样性有用，选择器是瓶颈 |
| 低温度 probe 分支 | 100 样 +2，200 样变负 | 不稳定 |
| 选择性双分支选择器 | GSM8K-200：62.0% vs LCR 60.5%（~1.37×） | 小增益，未达「强方法」 |
| Answer-evidence 选择器 | discovery 63%，holdout 61% | **负向泛化**，不作方法增益宣称 |
| response_refresh / lookahead | refresh 大幅掉点；lookahead 持平或略差 | 拒绝用即时局部置信收缩改顺序 |
| terminal_refine / 短验证 prompt | 基本不改答案 | 终局修补无效 |
| Risk-gated independent agreement | GSM8K-200：60.5%→62.5%（~1.2×）；新 400 样失败；合 600 样 McNemar p=1.0 | **已否决为可靠方法** |
| response_budget / persistence | budget 掉点；persistence 几乎不动 | 横向单独决定 wait/commit 不够 |
| response_alignment 稀疏探针 | 50% vs LCR 52.5% | 负结果 |
| **固定 32-token 分块** | 见 §5 主结果 | **当前最强正结果** |
| 固定 wavefront / response-decay wavefront | 65% / 55% vs 分块 72.5%（40 样） | 逐步 response 控波前失败 |

## 7. 给后续迭代的工作原则

1. **不要**再假设「正确 token 曾在轨迹中出现」——除非在**修复 ceiling 实现后**的新任务上测出非零 ceiling。
2. **不要**把逐步 response 幅度直接变成 commit 优先级或波前宽度。
3. **要**把横向/纵向当作「依赖是否解决」的结构信号，决策放在区域边界。
4. **要**在宣称方法增益前做 holdout / 跨切片；discovery 上的 +1～2 点不算数。
5. 固定分块是强基线与正对照，但写论文/方法声明时，最终主张应落在「轨迹如何决定区域」，而不是「人为设 32」。
6. **要**先消化 `0712grokproblem` 中的 P0/P1 评测 bug，再更新 H4 / HumanEval 叙事。
