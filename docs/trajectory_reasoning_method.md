# 横向与纵向轨迹如何进入生成决策

这项工作的核心不是融合旧 logits，也不是用更多统计量给 token 打分。我们把一次落定看作对可见上下文的真实改变，并保留其余未落定位置在这个改变前后的分布。横向和纵向描述的是同一个过程的两个阶段：横向回答“这次上下文改变影响了哪里”，纵向回答“这些影响后来是否被模型吸收并保持”。

## 横向：识别不能独立落定的位置

当一部分 token 落定后，我们比较其他仍遮蔽位置在落定前后的候选分布。明显变化说明这些位置依赖刚刚出现的上下文，因此不应被当作彼此独立的位置同时落定。当前实现使用共同 top-k 支持上的分布变化来观测这种响应，并检查响应随位置距离和区域边界如何分布。

横向信号只说明依赖存在，不直接说明哪个候选正确，也不直接推出“变化越大就等待越久”。先前按响应大小逐步缩小生成范围的实验已经失败，说明横向信息更适合确定生成的结构和范围，而不是充当逐 token 的置信度。

## 纵向：判断上下文影响是否已经稳定

对横向上受到影响的位置，我们继续跟踪其后若干去噪步的完整候选分布。若一次改变在后续步骤中保持，说明新上下文已进入该位置的持续判断；若候选迅速回摆或反复变化，说明依赖尚未解决。这里关注的不是单纯“多久没换 top-1”，而是落定引起的分布改变是否持续。

纵向稳定也不等于答案正确。它只能判断当前状态是否已经充分吸收可见上下文，不能独立承担候选选择。简单的翻转次数和跨分支一致性没有稳定超过基线，因此目前不再把纵向统计直接用于改写答案。

## 二者的统一落实

横向和纵向通过“上下文响应”相连：一次真实落定产生横向响应，随后多个去噪步形成该响应的纵向轨迹。算法决策因此应放在区域层面，而不是每一步为单个 token 叠加分数。

当前最可靠的落实是分区域顺序去噪：区域内保留多步去噪，使候选沿时间轴反复更新，这是纵向过程；前一区域完成后再向后一区域提供可见上下文，避免强依赖位置过早并行落定，这是横向过程。固定 32-token 区域在 400 个 GSM8K 样本、相同 64 NFE 下达到 71.25%，单区域 LCR 为 58.75%。这个结果支持“依赖发生在区域尺度、需要先形成上下文再继续”的判断，但固定分块本身还不是最终的轨迹方法。

真正待验证的一步是：只在一个区域完成后，利用它造成的横向响应及该响应随时间的保持或回摆，共同决定下一区域的范围。横向确定哪些位置仍受前文影响，纵向确定这种影响是否已经稳定；只有两者一致时才扩大并行落定范围。这仍是研究假设，尚不能写成已验证结论。

## 当前边界

目前已经明确排除三条路线：不融合历史 logits，不把稳定当作正确，不在每个 token 步骤上按响应大小频繁改变范围。现有证据验证的是区域化顺序生成的必要性和有效尺度；尚未验证的是由轨迹自动决定区域边界。后续工作应围绕这一处缺口展开，而不是继续增加独立特征、绘图或外围分析。
