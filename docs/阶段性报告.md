## 1. 核心结论（先说清楚）

到目前为止，**还没有找到能稳定超过基线的测试时方法**。更重要的是，Round 3 的天花板测量给出了比“方法没调好”更强的否定：

| 结论 | 证据 |
|------|------|
| **轨迹恢复天花板 ≈ 0** | GSM8K 19 道错题、MATH 26 道错题：答案区正确 token **从未**在任何去噪步成为 argmax |
| **错误是“稳定错”，不是“摇摆后选错”** | 错题从早期步起就锁定错误算术/符号结果 |
| **Flip 可作检测，不可作纠正（greedy）** | 错题答案区 flip 均值 4.27 vs 对题 2.51；但 T=0 下 BO2 重生成完全相同，增益 0 |
| **第一版轨迹调度伤基线** | GSM8K：LCR 62% → traj/rcr/lateral 均为 58% |

一句话：分布轨迹**有诊断价值**（尤其是答案区 flip），但在当前 greedy 设定下**几乎没有“把错改对”的恢复空间**；继续堆基于“曾经正确过”的采样器，前提不成立。

## 2. 问题设定与研究假设回顾

### 2.1 我们在研究什么

掩码扩散语言模型每一步都会对所有仍遮蔽位置给出完整候选分布。标准采样器只把其中一部分坍缩成词元，其余分布直接丢掉。主张：

- **纵向**：同一位置的分布轨迹，记录候选在不同可见上下文下是否稳定；
- **横向**：某次落定之后，其他位置分布如何变化，记录位置间依赖。

### 2.2 假设状态（含 Round 3–4 更新）

| 编号 | 假设 | 状态 |
|------|------|------|
| H1 | 路径长度 / 净位移 能区分收敛、振荡、冻结 | **部分证伪（度量失效）**：几乎全标成 frozen |
| H2 | 落定后响应矩阵稀疏，强耦合对不应同步落定 | **方向支持，信号过弱**（稀疏度 ~99.98%） |
| H3 | 用轨迹结构做调度，可超过低置信度基线 | **当前版本未成立**（58% < 62%） |
| H4 | 中间步曾正确、最终却错 → 测试时修正天花板 | **已测：GSM8K=0%，MATH=0%** |
| H5 | 答案区 flip 可检测错误并驱动 BO2 提升 | **检测有信号；T=0 纠正失败（增益 0）** |

### 5.1 H4 天花板 — GSM8K（Node 2）

定义：错题中，答案区（启发式末段位置）是否曾在任意步以 gold token 为 argmax。

| 项 | 值 |
|----|-----|
| LCR 准确率 | 62% (31/50) |
| 错题数 | 19 |
| ever-visited gold（≥30% 位置） | **0** |
| **ceiling_ratio** | **0.0%** |

解读：失败模式不是“中间对、最后选错”，而是**全程稳定算错**。基于“恢复正确候选”的采样器前提不成立。

### 5.3 Flip 诊断（Node 6）

| 区域 | 正确样本 (n=31) | 错误样本 (n=19) |
|------|-----------------|-----------------|
| 答案区 flip 均值 | 2.51 ± 2.06 | **4.27 ± 1.68** |
| 推理区 flip 均值 | 6.52 ± 2.37 | 5.83 ± 1.93 |
| Pearson r(推理 flip, 正确) | 0.149（弱，且方向与“错则更抖”相反） |

解读：

1. **答案区 flip** 可作为不确定性 / 错误检测代理（错题约高 70%）。
2. **推理区 flip** 不能可靠预测对错；对题反而略高。
3. Flip 适合 **DETECTION**，在 ceiling=0 下不适合当作 **CORRECTION** 的充分条件。

产物：`results/round3_flip/gsm8k_flip.json`  
脚本：`scripts/run_flip_diagnostic.py`

## 6. Round 4：Flip-gated Best-of-2（Node 6.1）

算法：LCR 生成并统计答案区 flip；若均值 > T=3.5，再跑一遍；一致则输出，不一致取 flip 更低者。

| 项 | 值 |
|----|-----|
| LCR | 62% (31/50) |
| Flip-gated BO2 | **62%** (31/50) |
| Gain | **0** |
| 触发二次生成 | 26/50 |
| 二次与一次预测不同 | **0/26**（temperature=0，确定性） |

阈值相对“是否错误”的混淆矩阵（触发=判为可疑）：

| | 错题 | 对题 |
|--|------|------|
| 触发 | TP=14 | FP=12 |
| 未触发 | FN=5 | TN=19 |

解读：阈值有一定检测能力，但 **T=0 下重生成无多样性 → 零纠正**。与 H4 一致。

产物：`results/round4_bo2/gsm8k_bo2_t3.5.json`  
脚本：`scripts/run_flip_bo2.py`

## 8. 对原有思考的修正（更新版）

1. **“去噪时间轴 = 可恢复的隐式思考”**  
   对旁观者可描述；但对错题而言，时间轴上**没有出现过正确答案候选**，谈不上恢复。

2. **“历史分布可直接融合 / 用几何量排序”**  
   Round 2 已伤基线；Round 3 进一步说明：缺的不是更复杂的融合，而是**正确候选根本不在轨迹里**。

3. **轨迹的合理角色**  
   更像 **不确定性诊断 / 拒答 / 选择性重采样（需温度或噪声）**，而不是“从轨迹里捞回正确答案”。

4. **数据集**  
   GSM8K 与 MATH 同构失败；下一优先验证域是 **代码（HumanEval）**——错误剖面可能不同（脚手架稳定、body 可变）。

## 10. 建议的下一步（按优先级）

1. **HumanEval（Node 5）**：测 pass@1 与 ceiling；若 ceiling>0，再谈轨迹门控。  
2. **若坚持 BO2**：必须 `temperature>0` 或显式噪声，否则与单次 LCR 同构。  
3. **选择性回答**：用答案区 flip 做拒答 / 置信度，报告 coverage–accuracy 曲线，而不是硬改答案。  
4. **不要**在未验证 ceiling 的任务上继续堆 identity/Jaccard 调度。
